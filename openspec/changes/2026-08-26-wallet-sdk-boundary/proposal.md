# Wallet SDK Boundary\n\n## Decision\nThe platform integrates the wallet repository only through a versioned capability SDK contract. The wallet repository remains the owner of signing, custody, balances, transaction construction, and authorization queues.\n\n## Preservation\nThis change is non-destructive. Existing wallet resources, provider adapters, and in-flight intents remain preserved. No keys, balances, or wallet state are copied into platform state.\n\n## Platform behavior\nThe platform may submit canonical intent digests and consume opaque authorization/evidence references. Availability is `unavailable` until SDK version, provider identity, signature algorithm, expiry, and verification evidence are confirmed.\n\n## Rejection\nDirect wallet imports, private-key material, signing operations, protocol transaction construction, and inferred approvals are rejected from the universal platform boundary.\n
